# CloudPay EDI 业务模型说明与主管部门咨询稿

## 第一部分：业务模型说明

### 1. 运营主体

上海申比芯人工智能科技有限公司运营 CloudPay 算力交易撮合与容量管理平台。

### 2. 平台参与方

- 企业采购方：在平台查找并采购算力服务；
- 企业供应商：提交企业资质和资源证明，经审核后上架算力商品；
- 平台运营方：提供身份核验、资源验真、商品审核、信息展示、询价撮合、容量预留、订单管理、计量验收、争议处理和技术服务；
- 银行或持牌支付机构：处理资金支付或提供合规支付能力。

首阶段只开放企业供应商。供应商状态为：待提交 → 审核中 → 已认证 → 受限 → 已暂停 → 已退出。认证信息至少每六个月复核，资源证明、许可或结算账户变化时触发即时复核。

### 3. 交易标的

- GPU 算力服务：按 GPU 型号、地区、时间窗口、卡时和交付形式销售；
- 模型 Token 实际用量：按具体模型、服务商、上下文档位、输入/缓存/输出价格类型、区域和有效期销售；
- Token 容量时或模型实例服务：按保证吞吐、限额、实例时长或服务档位销售，不与实际百万 Token 用量混为同一价格；
- 柜月：按机位、功率、网络、地区、期限和服务等级销售。

### 4. 商品上架

供应商提交商品后不直接公开。平台核验企业主体、资源归属、规格、可售容量、地区、时间窗口、交付形式、报价和服务等级。GPU 资源通过 AI 辅助审计和人工复核核定 KAI 标准卡时数。审核通过后才允许上架。

### 5. 交易机制

- 固定价购买：买方选择标准商品和数量，平台预留容量并生成订单；
- RFQ 询价：买方发布脱敏需求，供应商分别报价，平台标准化展示；
- 预留容量：买方预订未来时间窗口，具体预留费和取消规则写入合同；
- 双边置换：双方已验真容量按同一时点人民币标准化参考价形成价值快照，并通过订单补差和实际交付完成，不发行可流通代币或期货合约。

### 6. 收费模式

平台拟向供应商收取独立的平台技术服务费/撮合服务费。费率、计费基础、开票和退费规则在供应商协议、订单快照及平台规则中明确。

### 7. 资金路径

建议模式为：采购方向实际供应商的对公银行账户支付算力服务款，供应商向采购方开具算力服务发票；平台另行向供应商收取平台技术服务费并开具相应发票。平台内部系统仅记录订单、付款凭证、对账和状态，不开设个人钱包，不接受充值和提现，不将资金沉淀为平台余额。

如业务改为平台统一收款后分账给多家供应商，将在上线前接入持牌支付机构的合规分账产品，或在取得相应许可后运行。

### 8. 交付和售后

订单标注 API、远程登录服务器、专属实例或机柜服务等交付形式。平台记录交付凭据、使用时段、双源计量、验收、退款和争议。交付凭据使用一次性领取链接、短时凭据或采购方公钥加密。
