# CloudPay 容量账本、存入、锁定与取出规则（草案）

版本：V1.0

## 一、适用资源

本规则适用于进入 CloudPay 账本的 GPU 卡时、具体模型 Token 实际用量额度、Token 容量时/模型实例、NAS 和柜月服务。每种资源保留原始单位和产品属性，不因标准化估值而变成通用代币。

## 二、容量批次

每次存入形成不可覆盖的容量批次，至少包括：

- 批次 ID、供应商和资源 ID；
- 资源类型、型号/模型、服务商、地区；
- 原始单位、数量、可售时间窗口；
- 验真方式、证据摘要、审核人和审核时间；
- 交付形式、SLA、复验时间；
- 当前状态、乐观版本号和最后心跳；
- 规则版本和审计记录。

历史批次、订单、计量和结算记录只追加更正，不直接覆盖或删除。

## 三、可售容量

供应商可售容量计算为：

**可售容量 = 已验真存入 − 报价预留 − 订单锁定 − 交付中 − 已消耗 − 风控冻结**

界面应同时展示每个组成项及其对应订单/事件，避免只显示一个无法解释的余额。

## 四、存入流程

1. 供应商选择资源类型和接入模式；
2. 提交资源归属、规格、地区、时间、容量和交付形式；
3. 平台执行材料核验、远程测试、连接器采集或云只读 API 验证；
4. GPU 进行 AI 辅助审计和/或人工审计，核定 KAI 标准卡时数；
5. 审核通过后创建“已验真存入”批次；
6. 商品另经报价和内容审核后才公开上架；
7. 持续心跳、复验或异常检测可以改变未来可售状态，但不抹除历史。

## 五、预留和锁定

- 报价预留：固定价下单、RFQ 方案或未来预订暂时占用容量；
- 订单锁定：可信支付确认后正式锁定；
- 交付中：已下发任务或凭据，尚未完成验收；
- 已消耗：按计量和验收确认使用；
- 风控冻结：因异常、争议、监管、司法或安全事件不可新售。

容量预留使用数据库事务与乐观版本控制。所有写接口接受幂等键；跨服务事件通过事务事件盒和可重试消费者处理。任何扣减不得使可售容量小于零。

## 六、取出申请

供应商可对未被占用的容量申请取出。系统和工作人员至少检查：

- 申请人是否具有该容量批次操作权；
- 申请数量是否小于等于可售余额；
- 是否存在报价预留、订单锁定、交付任务、退款或争议；
- GPU/模型任务是否排空；
- NAS 数据是否完成迁移与删除确认；
- 是否满足提前通知期和合同约定；
- 是否存在风控、行政或司法冻结；
- 连接器/云只读验证是否仍能证明资源控制权。

## 七、取出结果

1. **立即取出**：全部申请容量无占用且满足条件；
2. **部分取出**：仅可售余额部分满足条件，剩余部分保留并说明原因；
3. **排期取出**：因未来已承诺服务、通知期、任务迁移或待复验，在具体日期释放；
4. **暂不允许**：存在争议、冻结、权限或证据问题，并提供处理入口。

取出只改变未来可售余额，不删除历史批次、订单、计量、支付和结算记录。

## 八、连接器失联

连接器失联不立即删除资源。平台执行：

1. 标记最后心跳和异常时间；
2. 停止新订单和新的报价预留；
3. 检查现有已锁定/交付中订单；
4. 通知供应商并启动重连、复验或人工处置；
5. 必要时执行替代资源、退款、赔付或争议流程；
6. 恢复后核对异常期间资源占用和计量，不自动恢复售卖。

## 九、重复承诺和超卖

平台检测相同设备摘要、云实例、配额、机柜和时间窗口是否重复存入或异常占用。确认超卖时，可冻结批次、停止供应商新订单、优先保障已付款订单、要求替代交付，并按违规和赔付规则处理。

## 十、人工操作和审计

任何人工增减、冻结、解冻、取出或状态更正必须记录操作人、理由、前后状态、审批证据、关联订单和全局事件 ID。高风险操作采用双人复核或强认证。
