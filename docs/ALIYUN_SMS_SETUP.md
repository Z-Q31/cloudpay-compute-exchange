# 阿里云短信登录注册上线清单

项目已包含完整短信登录注册链路：

- App 请求 `POST /mobile/v1/auth/otp/request`
- 后端生成 6 位验证码并调用阿里云短信服务
- App 请求 `POST /mobile/v1/auth/otp/verify`
- 后端一次性校验验证码，并完成登录或新用户注册
- 验证码 5 分钟过期；单手机号 10 分钟最多请求 3 次；HTTP 接口另有限流

## 1. 阿里云控制台申报

先完成企业实名认证和短信资质，再申请短信签名。App 尚未上架时，优先使用与营业执照一致的企业全称或企业简称作为签名。

签名通过后申请“验证码”模板，建议内容：

```text
您的验证码为：${code}，5分钟内有效，请勿泄露给他人。如非本人操作，请忽略本短信。
```

场景说明：

```text
本模板用于 KAI CloudPay App 用户手机号登录及新用户注册验证。用户在登录或注册页面填写手机号并主动点击“获取验证码”，系统发送6位数字验证码，验证码5分钟内有效，仅用于身份校验，不包含营销内容。
```

如果审核要求核验线上业务，请先使用阿里云控制台测试功能联调，App 上架后补充应用商店链接再申请正式模板。

## 2. RAM 权限

为后端创建独立 RAM 用户或角色，仅授予发送短信所需权限。不要使用主账号 AccessKey，也不要把 AccessKey 写入 App、APK、Git 或任何 `EXPO_PUBLIC_*` 配置。

## 3. 后端生产配置

在服务器的机密配置中设置：

```dotenv
SMS_PROVIDER=aliyun
SMS_ACCESS_KEY_ID=<RAM AccessKey ID>
SMS_ACCESS_KEY_SECRET=<RAM AccessKey Secret>
SMS_SIGN_NAME=<审核通过的签名原文，不含方括号>
SMS_TEMPLATE_CODE=<审核通过的模板 Code，例如 SMS_123456789>
```

模板变量名必须为 `code`，与后端发送的 `{ "code": "123456" }` 一致。修改配置后重启后端服务。不要把真实值提交到 `.env.example`。

## 4. 上线前验收

1. 用阿里云测试手机号分别完成一次注册和一次登录。
2. 确认错误验证码不能登录，验证码使用一次后立即失效。
3. 确认验证码超过 5 分钟失效。
4. 确认连续请求会触发频率限制。
5. 在阿里云控制台核对发送记录、失败原因和费用告警。
6. 正式放量前配置短信额度和异常发送告警。
